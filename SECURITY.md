## Reporting a Vulnerability

We take the security of Amala seriously. If you believe you have found a security vulnerability, please report it to us as described below.

### Please do NOT:

- Open a public GitHub issue
- Discuss the vulnerability in public forums or Discord servers
- Share the vulnerability with others until it has been addressed

### Please DO:

1. **Email security reports to**: [SECURITY_EMAIL_TO_BE_ADDED]

   Include as much of the following information as possible:
   - Type of issue (e.g., buffer overflow, SQL injection, cross-site scripting, etc.)
   - Full paths of source file(s) related to the manifestation of the issue
   - The location of the affected source code (tag/branch/commit or direct URL)
   - Any special configuration required to reproduce the issue
   - Step-by-step instructions to reproduce the issue
   - Proof-of-concept or exploit code (if possible)
   - Impact of the issue, including how an attacker might exploit the issue

2. **Allow time for response**: We will acknowledge receipt of your report within 48 hours and provide an initial response within 7 days.

3. **Allow time for fix**: We will keep you informed of our progress and coordinate the disclosure after the vulnerability has been fixed.

### Our Commitment

- We will respond to your report promptly
- We will keep you informed of the progress towards resolving the vulnerability
- We will credit you for the discovery (unless you prefer to remain anonymous)
- We will not take legal action against security researchers who:
  - Act in good faith
  - Do not access more data than necessary
  - Do not impact the availability or integrity of services and data
  - Report the vulnerability promptly and do not share it publicly before resolution

## Security Best Practices

If you are running your own Amala server, we recommend:

- Keep your server and dependencies up to date
- Use strong authentication and authorization mechanisms
- Regularly review access logs
- Implement proper network security (firewalls, VPNs, etc.)
- Encrypt data at rest and in transit
- Follow the principle of least privilege
- Regularly audit user access and permissions

## Security Updates

Security updates will be released as patch versions (e.g., 0.1.1, 0.1.2) and will be announced in our release notes. We recommend subscribing to releases to be notified of security updates.
